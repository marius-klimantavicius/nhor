# C11: bounded rich notes

`Marius.Winter.RichTextBox` and `Marius.Winter.Blazor.Elements.RichTextBox`
edit plain text with bold, italic, underline, strike and optional RGBA color.
The native renderer, metrics, selection and scrolling remain Winter's editor.
This is a bounded note editor, without HTML/Markdown, import/export, images,
paragraph layout or an operating-system document service.

```razor
<RichTextBox @ref="editor" @bind-Text="text" Placeholder="Write a note"
             ResetVersion="resetVersion" FormattingStateChanged="ShowFormat" />
<Button Text="Bold" OnClick="@(() => editor?.ToggleBold())" />

<RichTextBox @bind-Document="note" ResetVersion="documentResetVersion" />
```

`TextChanged(string)` is authoritative when it has a delegate;
`OnTextChanged(string)` is its compatibility fallback. Non-null
`Document` selects rich binding: `DocumentChanged(RichDocument)` is the editing
callback and `Text`/both text callbacks are ignored. Null `Document` returns to
plain text binding; null `Text`/`Placeholder` mean empty. Parameter application
never calls these application editing callbacks.

Equal text or equal rich-document parameters preserve selection, caret, run
styles, history and pending typing style. Changed external text replaces the
document with plain text; changed external document restores all its runs.
Both start a new history baseline. Increment `ResetVersion` for an intentional
equal-value reset, or to supersede an undelivered edit. In Text mode this also
clears all formatting. A delivered edit can be rejected by retaining the parent
value. With Text binding, format-only commands stay local to the editor; choose
Document binding to retain those edits in the parent.

Native `Text`/`Document` setters have the same equality policy. Explicit
`ResetText`/`ResetDocument` reset selection, pending style and history even for
equal values. Native legacy `TextChanged` still reports changed text, including
programmatic replacement. `DocumentChanged` reports document changes;
`UserTextChanged`/`UserDocumentChanged` distinguish editing commands from
synchronization. Programmatic `SetFormat`/`SetColor` participate in history
without synthesizing a user edit. Legacy `FormatChanged(TextFormat)` remains;
the additive `FormattingStateChanged(RichTextFormattingState)` reports flags,
color, mixed-selection indicators, selection offsets and undo/redo availability.
Formatting-state notifications also describe synchronized state.

Both APIs provide `ToggleBold/Italic/Underline/Strikethrough`,
`SetSelectionColor`, `ClearFormatting`, `Select`, `Focus`, `Undo`, `Redo`,
`CanUndo`, `CanRedo` and a readable formatting state. The wrapper exposes
`CurrentDocument` as an immutable snapshot, without requiring handler access.
Commands on an unmounted component reference are harmless. A format toolbar
retains the logical selection when its button receives focus, applies the
command and returns focus to the editor. At an empty selection, formatting
sets the typing style; Clear style sets plain typing style, including theme
color. Ctrl+Z undoes; Ctrl+Y and Ctrl+Shift+Z redo. One native text input,
paste, deletion, newline or selected formatting command is one history step.
The editor's optional logical `FontSize` does not mutate its shared theme.

Removing a native editor (including clearing its parent) releases its transient
run paints before scene removal. Reattaching it in the same Window rebuilds the
styled text while retaining document, history, selection/caret, pending typing
style and scroll. Detached editors remain caller-owned; dispose them before the
Window's graphics session ends. Formatting or restoring a snapshot and then
unmounting a Razor editor in the same UI turn is supported.

Editing events carry immutable snapshots and retain discrete edit order.
Reset, source-mode changes, parent corrections, callback replacement/clear and
removal invalidate undelivered events. Equivalent Razor method/target delegates
keep their subscription across unrelated renders. This local comparison uses
the current framework's EventCallback delegate/receiver fields; an unfamiliar
framework layout conservatively falls back to framework reference identity.
No shared renderer transport change is required.
Callback completion never writes an old value back into the component. Set
application state before awaiting work. Application operations that can finish
out of order still need cancellation plus generation checks and `InvokeAsync`
for owning-UI completion, as described in [input binding](input-binding.md).

## Document and history values

`RichDocument(text, runs)` copies input into read-only canonical runs. Runs
are sorted, nonoverlapping UTF-16 ranges with positive lengths; gaps become
plain, equal adjacent styles merge, and empty text has zero runs. Invalid
Unicode scalars, split surrogate pairs, unknown flags and nonfinite/out-of-range
color channels are rejected. `RichTextStyle` and `RichTextRun` are immutable
value records; changing an input collection or a copied Color4 cannot mutate
the document. Equality/hash include text and canonical flags/colors, never
selection, graphics ownership or history.

Offsets are UTF-16. `Replace(start, length, text, optionalStyle)` floors insertion
inside a grapheme to its preceding caret; nonempty deletion/replacement expands
to whole graphemes, including combining sequences, emoji and CRLF. Omitted
insertion style inherits the preceding scalar (the following scalar at zero).
`WithStyle` sets a complete style and uses scalar-safe ranges, as native
`SetFormat`/`SetColor` do. Styles may distinguish scalars within a grapheme;
interactive selection and deletion still move by entire graphemes. There is no
implicit Unicode normalization or newline rewriting.

Documents allow at most 262,144 UTF-16 code units and 16,384 canonical runs.
This bounds notes and snapshots; it is not a large-document performance claim.
`ToJson()`/`RichDocument.FromJson()` use schema `Version: 1`, text, and runs
with numeric flags and null/theme or four-channel RGBA colors. A snapshot
round-trips every style, including scalar styles, and is editable after restore.
Unsupported schema versions fail explicitly. Serialization performs no file I/O.
Glyphs and underline/strike honor the stored alpha, including transparent runs,
restored documents, reused paints and theme-color fallback. Glyph opacity and
decoration fill alpha each compose once with the editor's element opacity.

`RichDocumentHistory` is frontend independent. `Apply` records unequal values;
an equal-value no-op preserves redo. New edits after Undo discard redo.
`Reset` establishes an external baseline and clears both stacks. The default
64-step history has a constructor capacity of 1–256, evicting the oldest step.
Native RichTextBox uses this controller for both text and formatting. Selection
is clamped to legal carets on history navigation; it is not a serialized/history
document attribute. Clipboard paste is plain text and inherits insertion style.

## Playground hooks

Register native `new Scenarios.NotesScenario(window).Content` as **Notes**, and
dispose the scenario before closing its Window. The module also detaches its
subscriptions on normal close. Register Razor
`<Scenarios.Notes OwnerWindow="@OwnerWindow" />`. Both actual playground
entrypoints now register Notes alongside Project browser, Environment and tabs,
and the existing pages; existing galleries remain intact.

Both modules use the same two-line field note, toolbar and Reset. Razor starts
with Document binding; Replace plain selects Text binding, and Restore snapshot
returns to Document binding. Select and
style **blue horizon**, type with a pending style, clear styles, replace plain
text, save a versioned snapshot and restore its colors/styles. Undo/Redo cover
actual edits and formatting; Rerender preserves the current rich selection and
runs. The snapshot preview, format/history result, light/dark and larger-text
controls make those transitions visible.
