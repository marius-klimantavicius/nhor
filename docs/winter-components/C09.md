# Declarative menus and contextual commands

Native `MenuItemDef` has live `Enabled`, `IsChecked`, `Shortcut` and `Label` properties. Obtain the definition from `Menu.InsertItem` or `Entries`; existing fluent `AddItem`, `AddSeparator`, `AddSubMenu` and flat menu APIs remain available. `InsertSeparator` and `InsertSubMenu` return definitions for ordered edits. `MoveItem` preserves definition identity. Removing an item clears its action; a previously captured action also checks current membership, enabled ancestors and menu availability before invoking it.

Open popups refresh their actual rows, check marks, shortcut text and disabled colors when definitions change. Surviving highlighted definitions retain identity across reorder; removed or disabled entries lose highlight and cannot be activated by pointer or keyboard. Nested popup placement flips and clamps to the logical client area. Oversized menus clip to that area; arrows/Home/End reveal their highlighted row and the wheel scrolls rows. Long labels and informational shortcuts are clipped at the client boundary when they cannot fit. A shortcut label does not install a global key binding.

F10 enters the first active menu bar in the current modal scope. Tab can also focus a menu bar; Enter/Space/Down opens it. Up/Down and Home/End skip disabled entries and separators. Right opens a highlighted submenu; Left and Escape return one submenu level. Left/Right switch top-level menus when no nested branch consumes them. Enter/Space activates a command. Escape at the root closes it and restores its entry owner; Tab closes and resumes focus traversal. Typed characters do not edit the underlying focused editor while a menu owns input. A modal's default/cancel actions run only after its child menu has released the key scope.

Menu and Shift+F10 open the focused owner's context commands. Right-click uses the existing `Element.OnBuildContextMenu` contract, including built-in text editing menus. Live changes to `Element.ContextMenu` definitions refresh the open context popup; replacing the attachment dismisses it. Outside clicks, owner removal/inactivity, modal transitions and normal Window shutdown release menu captures, subscriptions and popup-owned paints. Detached application Elements and caller-owned menu services retain their existing ownership rules.

## Razor

```razor
<MenuBar>
    <Menu Title="Preview">
        <MenuItem Label="Save preview" Enabled="ready" Shortcut="Ctrl+S" OnClick="Save" />
        <MenuItem Label="Detailed view" @bind-IsChecked="detailed" />
        <MenuSeparator />
        <SubMenu Label="Zoom">
            <MenuItem Label="125%" OnClick="Zoom125" />
        </SubMenu>
    </Menu>
</MenuBar>
<Button Text="Preview">
    <ContextMenu><MenuItem Label="Inspect source" OnClick="Inspect" /></ContextMenu>
</Button>
```

These children are nonphysical definitions, with one ordered handler sequence for commands, separators and submenus. Use `@key` for dynamic commands and branches. Surviving definitions retain identity through compiled Razor reorder/update diffs; removal releases actions and mapping registrations. There are no arbitrary interactive row templates. A `ContextMenu` attaches to its physical parent. Removing it restores that parent's previous caller-owned context menu if the attachment still owns the property; it does not overwrite a later application replacement or dispose a service.

`IsChecked` is controlled state. With a checked callback, user activation proposes the toggled value. `IsCheckedChanged` is authoritative when `HasDelegate`; `OnCheckedChanged` is the compatibility fallback. Parameter synchronization is silent. A changed parent value applies immediately and invalidates obsolete pending checks and clicks; changing it back does not revive them. Accepted checked feedback preserves later queued activations, including their individual checked values and clicks. Parent rejection ends that pending sequence. `OnClick` runs after the checked callback and its feedback render, only while the originating command remains current. Increment `ResetVersion` for an intentional same-value reset that must invalidate pending commands.

Actions are discrete deliveries on the owning Window/renderer dispatcher. They capture the originating callback and command/owner identity; they are not scalar-coalesced or redirected to a newer callback. Replacement, clear, disable/re-enable, reset, command/branch removal, owner detach/reinsert, modal lifetime change or shutdown invalidates obsolete delivery. Equivalent method/delegate subscriptions survive an ordinary render, including compiled model-method checked setters and clicks with a distinct component event receiver. A different method, target or receiver invalidates the subscription. Supply stable delegates for dynamically created closures whose subscriptions should survive unrelated renders. An awaiting checked callback cannot start an action after its identity becomes obsolete; no completion writes newer state.

Context actions, including submenu descendants, also capture the physical attachment's revision. Replacing or clearing `Element.ContextMenu` invalidates queued and awaiting actions from the old attachment, even if that same menu is then restored. Updating definitions in the same attachment preserves valid deliveries. The attachment revision does not affect independent menu-bar commands or ownership of borrowed menus.

## Preview and commands modules

`Marius.Winter.Playground.Scenarios.PreviewAndCommandsScenario(Window)` exposes `Content` and `IDisposable`. Razor uses `Scenarios/PreviewAndCommands.razor`. Both show the same authored Harbor.svg preview, simulated conversion enabling Save even while Preview stays open, checked detailed view, nested zoom, context inspect/save, keyed zoom reorder/removal, detach/reinsert controls and Reset. Conversion has cancellation and generation checks and returns through the owning dispatcher. Saving is a visible simulation and writes no file. Native module closing cleanup releases retained detached controls before graphics shutdown.

Both playground entrypoints retain their first ten pages and append Asset catalog, Preview and commands, and Files, for thirteen pages. Modules stay mounted across navigation, preserving Profile identity. The native host retains module ownership and their early closing cleanup. The sample-only scenarios project is included in `Winter.slnx`.

Permanent tests cover actual compiled nesting/binding/diffs, callback precedence and lifetime, native live pixels, modal menu scope, owned-X11 pointer/keyboard/context paths, first-frame preview glyph/image pixels, open-popup state pixels, resize and normal close with a popup active. Qualification is Linux x64/glibc/X11/Xvfb/software Mesa, with light/default and dark/22-unit text on SW and software GL. No hardware GL, other-OS, high-DPI, IME, universal glyph coverage or accessibility certification is claimed. Menus add no global command-routing framework, native window, app dependency in Core, modal rewrite or general popover system.
