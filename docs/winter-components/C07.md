# C07: file and path pickers

`FilePickerController` and `IFilePickerProvider` are frontend-independent. `LocalFilePickerProvider`
enumerates and stats local paths. Neither the provider nor the picker writes file contents or creates
folders. `PickerPath` carries a path; accepted local results are absolute provider-normalized paths.
The optional provider root bounds navigation for fixtures/application scopes; it is not a symlink or
security sandbox. Directory contents are bounded by the caller's chosen scope; enumeration is lazy
by directory, without whole-disk expansion or virtualization.

`OpenAsync(mode, directory, filter, fileName)` starts a fresh session. OpenFile requires an existing
file; SaveFile accepts a new name or presents explicit overwrite confirmation for an existing file;
SelectFolder accepts the selected folder or the current directory. Back, Up, editable location/Go,
selection/activation, extension filters and typed filename are supported. Selecting a directory and
activating it navigates; the file action also enters a selected directory. Filters preserve directories
and compare file suffixes case-insensitively. An empty extension set accepts all files. Save names
must match the active filter; extensions are not silently appended.

Loading, empty and ordinary list/stat errors are visible. Retry re-enumerates the current directory.
Cancellation **and** generation checks protect navigation, filter changes, close/reset, provider
replacement and disposal, even when a provider ignores its cancellation token. `ConfirmOverwrite`
requires the current confirmation ID; an old Yes cannot accept a different name/session. The native
view uses one `ModalDialog`, switching its body for overwrite; it never nests a second modal.

`Completed(FilePickerResult)` captures session, mode, nullable path and overwrite permission. A
null path is user cancel. `Reset()` is silent and invalidates pending results; programmatic state
synchronization does not impersonate a user action. Notifications originate on the mutating thread;
native views marshal to their owning Window and detach subscriptions. A native `FilePicker` borrows
its controller and provider; detaching/resetting the presentation cancels its active session without
disposing those services. Dispose retained views before their graphics session ends. One presenting
view per controller is supported. Providers can be replaced without transferring their ownership.

Blazor `FilePicker` exposes `@bind-IsOpen`, mode, initial directory/name, filters, reset version,
Selected/Canceled and optional borrowed Controller/Provider. Without a Controller it owns its
controller. `IsOpenChanged` takes precedence over `OnIsOpenChanged`; results retain their request
identity. Parent close rejection and explicit resets are authoritative.

Native and Blazor `PathPicker` compose an editable field and Browse. `@bind-Value` is `PickerPath?`;
`ValueChanged` wins over `OnValueChanged`. Editing preserves incomplete/relative text for application
validation; Browse results are normalized. Cancel preserves the bound value. External value changes,
reset, readonly/disabled state and provider replacement invalidate old browse work. Readonly text
remains selectable. Label/help/validation and focus integrate with native Field and Blazor EditContext;
Blazor forms use `ValueExpression`, supplied by `@bind-Value`. `TextCommitted` flushes pending typed
state before Enter/blur actions; accepted Browse results also follow earlier scalar edits.

```razor
<PathPicker Label="Destination" @bind-Value="model.Destination"
            Provider="files" InitialDirectory="@fixtureDirectory"
            Mode="FilePickerMode.SelectFolder" />
<FilePicker @bind-IsOpen="saving" Provider="files"
            InitialDirectory="@fixtureDirectory" FileName="output.png"
            Mode="FilePickerMode.SaveFile" Filters="pngFilters" Selected="WriteAcceptedOutput" />
```

Converter retains its lazy C05 source sidebar, SVG/Lottie previews and PNG/GIF output. Open/Save use
these pickers. Conversion runs synchronously on its owning UI path and cannot be interrupted; there
is no conversion Cancel claim. C08 status/logs expose read/conversion/write errors and retry. Only the
application writes accepted output. A new target uses CreateNew to reject a concurrent creation;
an existing target uses Create only after explicit overwrite permission. Permission is not a lock
against later filesystem changes. Fixture parameters redirect both workspace and settings.

Installer uses the real local PathPicker, retains EditContext validation and its simulated install,
and composes C08 status/append logs with cooperative simulation cancel. It never performs installation.

Playground hooks (entrypoint registration is coordinator-owned): native
`new Scenarios.FilesScenario(window)` → `Content`, `IDisposable`; Razor `Scenarios.Files` with
`OwnerWindow`. Both expose Files, `/Files` deterministic data, all three modes, filters/name,
cancel/retry/overwrite, pending-list cancel/provider replacement, Reset and visible results. Shared
fixture data is linked by the Razor playground project. Font glyph fallback depends on installed
fonts; these fixtures preserve valid Unicode/graphemes without promising emoji font coverage.
