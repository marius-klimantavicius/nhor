# C02: environment selection and settings tabs

Winter's ComboBox and tab headers participate in Tab/Shift+Tab traversal and draw
a focus outline. A component reference can call `Focus()` on the owning UI thread;
it returns false for an inactive, detached, disposed, or non-focusable control.

## ComboBox

The existing string/index API and C01 binding contract remain available:

```razor
<ComboBox Items="environments" @bind-SelectedIndex="index" ResetVersion="reset" />
```

Enter or Space opens the list; a second Enter/Space commits its highlighted row.
Up/Down/Home/End open and navigate the list without changing the committed
selection. Navigation clamps at the first/last row. Escape, focus leaving the
chooser, an outside pointer press, or a second pointer press on the chooser cancels
the tentative choice. Tab closes the list and moves to the next control. Key repeat
can navigate but cannot repeatedly open or commit.

The popup snapshots its rows, clips text, caps its height to the available logical
viewport, flips above the chooser when that side offers more room, and clamps its
horizontal position/width. Its preferred height is at least 200 logical units or
six rows at larger fonts, bounded by available space. Keyboard navigation reveals
the highlight. Wheel, scrollbar page presses, and thumb dragging scroll without
committing. A row press computes its actual row immediately; it does not depend
on receiving an earlier hover/move. A matching row press/release commits once.
Window resize updates popup placement; disabling, hiding, removing, or disposing
the owner releases popup/capture/focus state. Option batches and theme/font updates
close an obsolete popup snapshot.

`IsDropDownOpen` and `HighlightedIndex` expose read-only native state.
`SelectedIndex`, `SetItems`, `SetItemsAndIndex`, and legacy `SelectionChanged`
retain their existing programmatic semantics. Only a changed user selection emits
`UserSelectionChanged`; Escape and selecting the already-committed item do not.

## Typed selection

Both frontends have `Select<TItem,TValue>`; native also exposes the plain C#
`SelectController<TItem,TValue>`, which needs no Window or Blazor dependency.

```razor
<Select TItem="EnvironmentOption" TValue="string"
        Items="options" TextSelector="@(e => e.Name)" ValueSelector="@(e => e.Id)"
        @bind-Value="environmentId" ResetVersion="reset" />
```

Native callers can set `TextSelector`, `ValueSelector`, `Items`, `Value`, and
`ValueComparer`, or call `Configure(items, textSelector, valueSelector, value,
comparer)` to validate/apply the complete state atomically. The controller offers
the same configuration and `SetItems`, `SelectIndex`, `ClearSelection`,
`SelectedIndex`, `SelectedItem`, `HasSelection`, `StateChanged`, `ValueChanged`,
and `UserValueChanged`. The native facade exposes its `Controller`,
`SelectedOption`, and the inherited display string `SelectedItem`.

Values are identity keys. `EqualityComparer<TValue>.Default` is the default;
`ValueComparer` can supply another equality policy. Duplicate labels are allowed.
Duplicate values under that comparer, or null option values, throw before changing
the previous state. Selectors should be pure; option sequences are snapshotted.
Replacing/renaming/reordering items follows the selected value, never its former
index. Removing a selected key leaves `Value` unmatched and the display empty;
reintroducing the key restores its selection. Neither transition fabricates a user
edit. `Items = null` empties the options while retaining that requested value.

Null `Value` means no selection for reference/nullable types. Every value, including
zero/default, remains a valid key for non-nullable value types. Native
`ClearSelection()` explicitly clears even those types until another value is set;
use a nullable `TValue` for a clearable Razor numeric binding.

Razor `ValueChanged` takes precedence over the legacy `OnValueChanged` fallback.
Programmatic synchronization does not invoke either callback. Events carry a
typed value snapshot, independent of later index changes. Equal ordinary renders
preserve queued input; reset/version, changed authoritative options/value,
replacement callbacks, and removal invalidate obsolete queued state. Parent
rejection produces an actual native correction even when its declared value is
unchanged. See [C01 input binding](input-binding.md) for async callback identity
and application cancellation/generation rules. A newly-created callback identity,
including a generated get/set binding delegate, has the same replacement semantics.

## Tabs

```razor
<TabWidget @bind-ActiveTab="activeIndex" ResetVersion="reset" @ref="settings">
    @foreach (var page in pages)
    {
        <Tab @key="page.Id" Label="@page.Name" Enabled="@page.Enabled"
             Visible="@page.Visible"><Label Text="@page.Description" /></Tab>
    }
</TabWidget>
```

Left/Right wrap among available headers; Home/End select the first/last available
header. This applies while the header strip owns focus; arrows bubbled from a
content editor do not change tabs. The selected header is revealed within a
clipped strip when the window is narrow. `ActiveTab = -1` explicitly clears all
tab content; selecting an available index resumes normal selection.

Native `ActiveTabChanged` reports index changes, including setters and structural
edits; `UserActiveTabChanged` reports changed pointer/keyboard selection only.
`ActiveContent` exposes selected content identity. Native `SetTabEnabled(content,
bool)` and `SetTabVisible(content, bool)` set header availability; content visibility
itself remains managed by TabWidget. Disabled/hidden headers cannot be selected.
Removal/disable/hide falls forward from the old position, wrapping to an available
neighbor, or to -1 when none exists. Detached tab content remains caller-owned.

Omitting `ActiveTab` in Razor leaves native identity-preserving selection intact on
ordinary renders. Keyed moves preserve the selected content and adjust its native
index. An unchanged supplied index also does not override such a keyed move;
changed supplied values and `ResetVersion` explicitly select by the new index.
Structural index changes are not wrapper user-change callbacks. A parent that
displays/stores indices should update its index alongside its keyed collection
mutation, as the scenario does. Pending user indices are invalidated when native
structure changes their meaning. `ActiveTabChanged` is authoritative when it has a
delegate; `OnActiveTabChanged` is the fallback, with no duplicate delivery.

## Playground modules and limits

Native `EnvironmentAndTabsScenario(Window)` exposes `Content` and `IDisposable`.
Razor `Scenarios/EnvironmentAndTabs.razor` offers the same 24 environments,
description/results, rename/reorder/remove/clear/Reset actions, and controlled
General/Details/Access settings. Register the native content with
`ScenarioHost.AddScenario("Environment and tabs", scenario.Content)` and the Razor
component in the existing scenario host. Host registration is an integration step.

Qualification covers Linux x64/glibc, private X11/Xvfb, software rendering and
software Mesa GL, normal close, light/dark themes, larger logical fonts, and narrow
viewports. It does not certify other platforms, hardware GL, high-DPI screens,
IME/accessibility, editable autocomplete, popup templates, or virtualized datasets.
Long labels are clipped to the control/viewport. The independent intermittent
idle-CPU threshold finding remains open.
