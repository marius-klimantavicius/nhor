# C04: native fields and Winter Blazor forms

Native `Field(label, editor)` composes one native editor with a wrapping associated
label, `HelpText`, and `SetMessages(IEnumerable<string>)`. `Messages`, `Invalid`,
`ReadOnly` (for TextBox/TextArea), `Enabled`, and `FocusEditor()` support ordinary C# form policy. Custom editors supply their own read-only policy. Label
presses focus the attached, enabled editor; read-only text remains focusable.
Read-only and disabled labels include a visible suffix. Messages retain normal theme contrast;
text-input borders independently show explicit invalid state. `Gap` is logical
spacing. TextBox's existing `Required` empty-text border still applies.

The editor remains caller-owned: assigning another `Editor`, removing the field,
or disposing it does not dispose the editor. Dispose retained editors before their
graphics session closes. The field owns/disposes its label/help/message resources.
The Blazor renderer owns its editors and disposes them on removal.

`TextBox` and `TextArea` expose `ReadOnly` and `Invalid` natively and in their
scalar wrappers. Read-only blocks typing, paste, cut, deletion, and multiline
newlines, including stale context-menu mutation actions. Arrows, selection,
Select All and Copy remain available. `Text`/`ResetText` synchronization is allowed
and produces no user-edit echo. C01 commit behavior and Unicode grapheme boundaries
are preserved.

Native `Form` is a vertical panel. Each `Field.Validate` returns ordinary C#
messages. `Submit()` evaluates available fields, focuses the first invalid editor,
and invokes `InvalidSubmit` or `ValidSubmit` once. `Reset()` invokes
`ResetRequested` so the owner restores its values, then clears field messages.
An external adapter can handle `SubmitRequested` from `RequestSubmit()` instead.
Native async/busy policy remains with the application; synchronous reentry is
guarded. There is no native reflection or dependency on Blazor validation.

TextBox handles Enter by synchronously committing/flushing its edited text, then
bubbling once. The nearest Form consumes it, including unchanged/read-only input;
repeat and Ctrl/Alt/Super Enter do not submit. There is no global Window key
subscription. TextArea consumes Enter/newline and Ctrl+Enter/commit. ComboBox
consumes popup Enter. This leaves a containing modal's bubbled default action
available when no nearer form consumes the key. Pointer actions use normal blur
commit behavior. C06 integration is a separate coordinator check.

## Blazor API

```razor
<WinterForm @ref="form" Model="model" OnValidSubmit="Submit"
            OnInvalidSubmit="Invalid" OnReset="ResetModel">
    <TextField Label="Application name" @bind-Value="model.Name" />
    <TextField Label="Destination" @bind-Value="model.Destination"
               ReadOnly="readOnly" HelpText="Use an absolute destination." />
    <SelectField TItem="EnvironmentOption" TValue="string" Label="Environment"
                 Items="options" TextSelector="@(e => e.Name)"
                 ValueSelector="@(e => e.Id)" @bind-Value="model.Environment" />
    <CheckboxField Label="Shortcut" Text="Create desktop shortcut"
                   @bind-Value="model.Shortcut" />
    <Button Text="Submit" OnClick="@(() => form.SubmitAsync())" />
    <Button Text="Reset" OnClick="@(() => form.ResetAsync())" />
</WinterForm>
```

Supply **exactly one** of `Model` or `EditContext`. `CurrentEditContext` is the real
Microsoft `EditContext`; the form creates one for Model and never disposes a
caller-supplied context/model. Built-in synchronous DataAnnotations validation is
enabled by default (`DataAnnotations=false` disables this form's subscription).
`Validation` accepts `Action<EditContext, ValidationMessageStore>` for additional
synchronous rules, called on field change and full validation; its form-owned
store is cleared before each call. The form does not implement async validation.

Adapters use `ValueExpression` (supplied by ordinary `@bind-Value`) for the actual
`FieldIdentifier`, notify `EditContext.NotifyFieldChanged`, and display that
field's messages. `ValueChanged` wins when it has a delegate; `OnValueChanged` is
the fallback. Assignments/reset do not notify user callbacks. Rejection by the
parent corrects native text. `TextField` additionally supports `Placeholder`,
`Required`, `TextCommitted`, and `Multiline`/`MultilineHeight`. SelectField delegates
typed identity/comparison to C02 Select. Standalone `Field` can compose another
single Winter editor; standalone adapters can also use a supplied cascading
EditContext without WinterForm.

`SubmitAsync()` validates before invoking `OnValidSubmit(EditContext)` or
`OnInvalidSubmit(EditContext)`; pending submit callbacks suppress duplicate
requests. Focus selects the first registered available invalid editor. Model-level
validation errors without a field have no focus target. All model properties
participate in full DataAnnotations validation, even when their editor is removed.
Registration order follows mounted fields; applications should order invalid
fields consistently when dynamically moving them.

`ResetAsync()` invokes the owner's `OnReset` callback first. The owner decides how
to restore model values; omitting it means clear-validation/reset-input state only.
Then the form clears **its own** validation stores, marks the context unmodified,
and resets queued native input. Other owners' message stores survive. Reset of the
same model preserves editors. Replacing the Model or EditContext establishes a
new context lifetime and remounts its fields; do not retain old native editor
references. Fixed cascades within a lifetime prevent validation renders from
reapplying obsolete direct parameters and disturbing the insertion point.

Replacement/unmount detaches DataAnnotations, field-validation and registration
subscriptions. Async change/reset/submit callbacks retain their originating model
identity; the form performs no late field notification or reset against a newer
context. Applications still own assignments made after their own awaits and must
use cancellation/generation checks for that work, as in C01.

Production adds only `Microsoft.AspNetCore.Components.Forms` **8.0.0**, matching
the existing Components **8.0.0** line. No framework upgrade, HTML EditForm/InputBase
output, or renderer change is involved. Production net8 and tests net9 compile and
run against that reference.

## Demos and qualification

Both modules are named **Installer setup**, with MyApp, `/opt/myapp`, stable
production/staging/development identities, shortcut, optional multiline notes,
read-only destination, disabled notes, protected-name rejection, Submit/result, Reset,
configuration replacement and notes removal. Native module:
`Scenarios/InstallerSetupScenario(Window)`, `Element Content`, `IDisposable`.
Razor module: `Scenarios/InstallerSetup.razor`. Both playground hosts register
Installer setup after the existing eight pages, beside Windows and dialogs.

Actual InstallerExample configuration uses the same reusable fields, real
EditContext/DataAnnotations and typed environment selection. It retains the sample
Browse tree, adds reset/new-draft/read-only actions, and keeps installation a
simulation. Completion preserves environment/shortcut/startup choices. Its owned
simulation is Task-returning, cancellation/generation guarded, dispatched to its UI,
and cooperatively awaited during shutdown. No filesystem installation occurs.

Qualified scope: Linux x64/glibc, private X11/Xvfb, SW and software Mesa GL, normal
keyboard/pointer interaction and WM_DELETE_WINDOW, light/dark, larger logical text,
and narrow resize. Small windows scroll to additional fields/actions. No new
hardware GL, other OS, high-DPI, IME, accessibility, async-validation, schema,
filesystem-browser or full forms-framework certification. The independent
intermittent idle-CPU finding remains open.
