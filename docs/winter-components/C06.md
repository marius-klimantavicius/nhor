# In-window modal dialogs

`Marius.Winter.ModalDialog` presents inside its owning `Window`; it never creates
another native window. One modal may be open at a time. Existing `DialogWindow`
remains draggable, resizable and modeless.

```csharp
var editor = new TextBox("Marius");
var actions = new Panel { Layout = new FlexLayout { Gap = 8 } };
var modal = new ModalDialog {
    Title = "Edit profile", Body = editor, Footer = actions,
    InitialFocus = () => editor,
    DefaultAction = token => ValueTask.FromResult(!string.IsNullOrWhiteSpace(editor.Text))
};
actions.AddChild(new Button("Save") {
    Clicked = () => _ = modal.RequestCloseAsync(DialogCloseReason.Accepted)
});
actions.AddChild(new Button("Cancel") {
    Clicked = () => _ = modal.RequestCloseAsync(DialogCloseReason.Cancel)
});
window.AddChild(modal);
modal.Closed += result => { if (result.Accepted) SaveProfile(editor.Text); };
modal.IsOpen = true;
// Before the graphics session ends: modal.Dispose(); editor.Dispose(); actions.Dispose();
```

Body and Footer are **borrowed** native roots. They must be live and detached
when assigned. Replacing a slot or disposing the host detaches its root without
disposing it. Closing detaches the presentation while retaining its slot roots
for reopening. Native callers dispose their retained roots before the owning
graphics session ends, normally in `Window.Closing`; also dispose an unused,
never-attached host. Caller-owned services and action delegates are never disposed.

```razor
<ModalDialog @ref="dialog" @bind-IsOpen="editing" Title="Edit profile"
             DefaultAction="Validate" Closed="Completed">
    <Body><TextBox @bind-Text="draftName" /></Body>
    <Footer>
        <Button Text="Save" OnClick="@(() => dialog!.RequestCloseAsync(DialogCloseReason.Accepted))" />
        <Button Text="Cancel" OnClick="@(() => dialog!.RequestCloseAsync())" />
    </Footer>
</ModalDialog>
```

Razor supplies `Body`/`Footer` fragments; the renderer owns and disposes their
elements. `InitialFocus` accepts `Func<WinterComponentBase?>`, e.g. a live
`TextBox` component reference. `IsOpenChanged` wins over legacy
`OnIsOpenChanged` when it has a delegate. Each completed user close sends false
once and then `Closed(DialogResult)`. Results contain `SessionId`, `Reason` and
`Accepted`; callbacks are captured when the request begins and are invoked before
awaiting either callback. Later continuations never write the modal's state.

Programmatic `IsOpen` changes, reset, hide and conditional unmount emit no user
close/result. A parent can reject false by continuing to declare true: that
reopens with a new session. Increment Razor `ResetVersion` (native
`ResetSession(bool)`) to invalidate an awaiting request or deliberately reopen
even when the declared bool is unchanged. Ordinary rerenders preserve a pending
request. After unmount/disposal no completion emits a result.

`CloseRequested` observes a request; `CloseRejected` observes validation/policy
rejection. Neither implies completion. `DefaultAction(CancellationToken)` runs
only for Accepted requests; false keeps the dialog open. Then optional
`CloseGuard(DialogResult, CancellationToken)` decides every reason. Both return
`ValueTask<bool>` and run on the owning UI dispatcher (Razor delegates also enter
the renderer dispatcher). Awaiting requests ignore further requests and repeated
keys. Reset, close, removal, policy replacement and shutdown cancel the token and
invalidate the generation. A guard must cooperate with cancellation and check its
token before changing application state after an await. Ordinary guard exceptions
reject the request; native `LastCloseError`/`CloseFailed` expose the error.

Escape first dismisses a child chooser/context popup, then requests modal close
when `CloseOnEscape` is true. Backdrop clicks are blocked; they request close only
with `CloseOnBackdrop`. `ShowCloseButton` controls the title close action.
Tab/Shift+Tab remain inside eligible modal controls and scroll a focused slot
control into view. Focus initially chooses the requested eligible descendant,
then body, footer and close-action fallback. Close restores an attached eligible
opener or the first eligible background control. Popup/capture state is released.

Default Enter follows child-first bubbling. TextBox commits its current edit
before the modal default; TextArea and RichTextBox retain multiline Enter;
ComboBox and explicit child buttons retain their own actions. A nested form may
consume bubbling Enter without forwarding it; it then owns submission and the
modal default does not also execute. Set its valid-submit action to request an
Accepted close. There is no global form/command service in this component.

Modal `Width`/`Height` are logical preferred sizes, applied on each layout and
clamped to the current viewport with an eight-unit outer margin. Header/footer
remain separate from the scrolling body; oversized footers can scroll too. Supply
a compact footer. At extremely small client sizes content necessarily clips;
the exercised small size is 340×240 with 22-unit text. The existing modeless Razor
`DialogWindow.Width`/`Height` initialize size; subsequent ordinary rerenders leave
user geometry intact. Modal presentation is centered, without dragging/resizing
chrome, a modal stack, OS dialogs or a general popover service.

Both playground modules demonstrate “Windows and dialogs”: transactional profile
editing, validation, Save/Cancel/default/Escape, a background counter, backdrop
policy, asynchronous unsaved-edit protection, removal/recreation, opener removal,
Reset and separate modeless Settings. Host registration is an integration step.
Qualification covers Linux x64/glibc, owned Xvfb, software rendering and software
Mesa GL; it makes no new other-platform, hardware-GL, IME or accessibility claim.
